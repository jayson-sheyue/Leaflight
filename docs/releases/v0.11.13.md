# Leaflight v0.11.13

2026-11-03 · Apple Silicon macOS · App 签名修复

## 已确认的原因与修复

v0.11.12 的 GitHub DMG 下载摘要和磁盘映像均正常，但包内 App 的严格签名检查失败：`code has no resources but signature indicates they must be present`。此前只验证本机启动和 DMG 完整性，没有拦住此签名问题。

- 对主 App、Helper 和框架执行完整 ad-hoc 签名，封装 Info.plist 与资源；为 Electron 配置 JIT 和 ad-hoc 框架加载所需权限。
- 启用强制签名，在签名结束及复制入 DMG 前执行 `codesign --verify --deep --strict`，同时核对 App ID、版本与资源封装。
- 新增真实签名回归：有效资源封装通过，未签名、版本错误和签后篡改被拒绝。
- 以新版本发布，不覆盖旧 tag 或原安装包；旧版说明标注已知签名问题。

## 安装边界

**本版没有 Developer ID 和 Apple 公证。** Ad-hoc 能修复签名完整性，但不提供 Apple 认证的开发者身份；本机 Gatekeeper 评估仍返回拒绝，不能宣称其他 Mac 默认双击即可打开。

确认来源和摘要后，可按 [安装说明](../macos-installation.md) 查看 Apple 官方针对单个 App 的允许入口；该入口可能受系统版本或管理策略限制。仍报损坏或无允许入口时，请反馈完整报错。完整默认信任体验需要后续 Developer ID 签名和公证，不要求用户关闭全局保护或移除隔离标记。
